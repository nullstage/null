## AI-001 — 미결정 사항 도출

### 목적

`MVP_PLAN.md`와 `CLAUDE.md`를 대조해, 구현을 시작하기 전에 결정해야 할 항목을 빠짐없이 뽑아내기 위해서다.

### 사용 도구

Claude Code (Opus 5)

### 대표 프롬프트

```text
MVP_PLAN.md랑 CLAUDE.md 읽고 결정해야 할 사항들 뽑아줘
```

### AI 제안 요약

기존에 등록된 OQ-001~006 외에 미등록 상태로 구현을 막는 항목 13개를 추가로 지목했다.
특히 다음 세 가지를 문서 간 모순 또는 정의 누락으로 지적했다.

- 방 2 구성이 방 1 분석을 반영하는지가 §2와 §9에서 엇갈린다. 반영하지 않으면 카운터 체험이 런당 1회뿐이다.
- 보스 최종 성향을 어떤 데이터로 산출하는지가 §8에 없다.
- 카운터 예고의 공개 범위가 없어 역기만이 우연에 가까워진다.

그 밖에 플레이어 체력 수치, 방 1·2 프리셋, 강화 지급 횟수, 결과 리포트 항목 등이 미정이라고 정리했다.

### 최종 반영

지적된 항목을 `docs/OpenQuestions.md`에 OQ-007~025로 등록했다.
다만 권장안을 확정하지는 않고 전부 `OPEN` 상태로 남겼다.

### 사람의 수정 및 판단

- AI가 제시한 권장안을 그대로 채택하지 않았다. 지금은 뼈대 단계이므로 정책을 미리 고정하면
  전투 감각이 나온 뒤 되돌리는 비용이 더 크다고 판단했다.
- 대신 "코드에 값이 필요하면 임시값을 쓰되 `OQ-XXX 미결정` 주석을 단다"는 규칙을 세워
  임시값과 확정값을 구분할 수 있게 했다.

## AI-002 — 프로젝트 뼈대 구성

### 목적

팀원이 전투 구현에 바로 들어갈 수 있도록, 계약과 시스템이 동작하는 뼈대를 만들기 위해서다.

### 사용 도구

Claude Code (Opus 5)

### 대표 프롬프트

```text
Phaser next js gsap emotion 이 스택을 팀원이 사용할거라서 이걸로 해주고
캐릭터 움직임이랑 전투, 보스 전투 디자인 패턴 등등은 팀원이 담당할거라 틀만 잡아두면 될 것 같아.
아트 에셋들도 나중에 추가할거고. BGM도 나중에 추가할거야. 지금은 약간 뼈대를 잡는다고 생각하면 돼.
결정해야할 것들은 미리 확정지어놓지 말고 문서에 남겨둬 나중에 하나하나 결정할거야.
틀을 잡을때 결정해야할게 있으면 다시 물어봐줘
```

### AI 제안 요약

뼈대 구조를 되돌리기 어려운 지점 세 가지를 먼저 질문으로 올렸다.

1. UI를 Phaser 내부에 둘지 React DOM 오버레이로 둘지
2. 스텁의 깊이 (계약만 / 최소 동작 / 프로젝트 설정만)
3. 배포 파이프라인을 지금 세팅할지

이후 이벤트 버스를 경계로 Phaser와 React를 분리하고, 시스템(텔레메트리·Director·런 상태·강화)은
동작하게, 전투(플레이어·적·보스)는 시그니처만 있는 스텁으로 만드는 구성을 제안했다.

### 최종 반영

- UI는 React DOM 오버레이, 통신은 `EventBus` 단일 경로로 확정 (DEC-006)
- 시스템 레이어 구현, 전투 레이어는 스텁 (DEC-007)
- 정적 내보내기 + GitHub Actions 배포 워크플로 작성 (DEC-005)

### 사람의 수정 및 판단

- **Phaser 버전을 4에서 3으로 되돌렸다.** npm 최신 설치가 Phaser 4를 가져왔으나,
  `MVP_PLAN.md`와 `CLAUDE.md`가 Phaser 3 전제로 작성돼 있고 팀원이 참고할 전투·보스 구현 자료도
  3 기준이 압도적으로 많아 4일 일정에서 위험하다고 판단했다.
- 전투 스텁에서 `telemetry.record*()` 호출만은 미리 심어두게 했다. 이 호출이 빠지면
  Director 분석이 통째로 무너지는데, 나중에 넣으면 빠뜨리기 쉬운 지점이기 때문이다.
- 적이 스텁이라 방이 클리어되지 않아 흐름 검증이 불가능했다. 개발용 방 스킵 키(F2)를 추가하도록 했다.

### 관련 파일

`src/game/**`, `src/components/**`, `app/**`, `next.config.mjs`, `.github/workflows/deploy.yml`

## AI-003 — 뼈대 동작 검증

### 목적

빌드 성공만으로 완료 처리하지 않기 위해, 실제 브라우저에서 전체 흐름과 분류 규칙을 확인했다.

### 사용 도구

Claude Code (Opus 5), Playwright(Chromium)

### 대표 프롬프트

```text
playwright mcp 이용해
```

### AI 제안 요약

정적 산출물을 로컬 서버로 띄우고 Playwright로 구동해, 시작부터 결과·재시작까지 관통하며
콘솔 오류와 각 단계의 화면 텍스트를 수집했다. `DirectorPolicy`는 순수 함수라
별도 스크립트로 MVP_PLAN §4·§5·§6·§8 규칙을 직접 대조했다.

### 최종 반영

검증 중 발견한 결함 세 가지를 수정했다.

1. Emotion 스타일이 프리렌더 HTML에 없어 발생한 React #418 하이드레이션 오류
   → `EmotionRegistry` 추가
2. 보스전 HUD가 `ROOM 0`으로 표시되던 문제 → 보스전 HUD 갱신과 `BOSS` 표기 분기
3. 재시작 후 이전 런 HUD가 남던 문제 → 재시작 시 HUD 상태 초기화, 전투 단계에서만 노출

### 사람의 수정 및 판단

- Playwright MCP 서버가 세션에 연결돼 있지 않아, MCP 대신 Playwright를 직접 구동하는 방식으로 진행했다.
- 첫 검증에서 캔버스 픽셀 샘플링이 "빈 화면"으로 나왔으나, WebGL 캔버스는 `preserveDrawingBuffer` 없이는
  읽을 수 없어 생긴 측정 오류였다. 스크린샷으로 실제 렌더링을 확인해 오탐으로 판정했다.
- 테스트 프레임워크(OQ-023)가 미결정이라 검증 스크립트를 저장소에 커밋하지 않고 일회성으로만 사용했다.

### 관련 파일

`src/components/EmotionRegistry.tsx`, `src/components/HUDOverlay.tsx`, `src/game/scenes/BossScene.ts`, `app/layout.tsx`

## AI-004 — 시작 화면 Figma 디자인 구현

### 목적

Figma에 그려진 시작 화면(node `1:33`)을 코드로 옮기고, 전달받은 이미지 4장을 저장소에 정리해 배치한다.

### 사용 도구

Claude Code (Opus 5), Figma MCP(`get_design_context`·`get_screenshot`·`get_metadata`), Chrome MCP

### 대표 프롬프트

```text
메인화면부터 작업해보자. src 폴더에 내가 배경, 타이틀, 서브타이틀, 장식을 넣어놨어.
이거 위치 알맞은곳에 옮겨주고, 파일 이름도 알맞게 고쳐주고,
피그마 화면 확인하고 똑같이 구현해보자.
(Figma node 1:33)
```

### AI 제안 요약

Figma MCP로 노드의 좌표·색·서체를 받아 Tailwind 참조 코드를 얻고, 이를 프로젝트 스택
(Emotion styled + `assetPath()`)으로 옮겼다. 1920×1080 디자인 좌표를 그대로 쓰기 위해
`--u = min(100vw, 100dvh × 16/9) / 1920` 하나만 두고 모든 값을 `calc(var(--u) * N)`으로 적었다.
시작 화면을 Phaser가 아닌 React 레이어로 두고 `ReadyScene`은 `ui:continue`만 기다리게 했다.

### 최종 반영

- `src/components/ui/TitleScreen.tsx` 신규, `HUDOverlay`에서 `phase === "READY"`에 렌더
- 이미지 4장을 `public/assets/title/`로 이동하고 이름 정리
- `ReadyScene` 단순화, `RunState.reset()`의 `phase:change` 미발행 결함 수정

### 사람의 수정 및 판단

- `get_metadata`가 장식 노드의 y를 `718.33`으로, `get_design_context`의 CSS는 `52.68%`(≈`568.94`)로
  다르게 보고했다. 스크린샷과 대조해 CSS 값이 맞다고 판정하고 그쪽을 채택했다.
- 참조 코드에는 배경 위에 `rgba(0,0,0,0.46)` + `blur(6px)` 오버레이가 있었으나,
  전달받은 `background.png`가 이미 그 합성 결과였다. 그대로 넣으면 이중 적용이라 오버레이를 삭제했다.
  (Figma가 내보낸 원본 배경과 로컬 파일을 눈으로 대조해 확인했다.)
- 장식 이미지는 Figma에서 `rotate(180deg) scaleX(-1)` 상태였다. 로컬 파일과 Figma 내보내기를
  대조해 상하 반전이 맞다고 확인한 뒤 `scaleY(-1)`로 옮겼다.
- 노션 링크(사전과제 MVP 문서)는 비공개라 열지 못했다. Figma만 근거로 진행했고 사용자에게 알렸다.
- Figma 화면에 조작 안내가 없어 기존 `ReadyScene`의 안내 텍스트가 사라졌다.
  임의로 되살리지 않고 OQ-026으로 등록했다.

### 관련 파일

`src/components/ui/TitleScreen.tsx`, `src/components/HUDOverlay.tsx`, `src/game/scenes/ReadyScene.ts`,
`src/game/systems/RunState.ts`, `src/styles/theme.ts`, `app/globals.css`, `public/assets/title/*`

## AI-005 — 로딩·시작 화면 연출과 화면 전환

### 목적

시작 화면에 게임다운 등장 연출을 넣고, 로딩 화면과 화면 전환(검은 페이드)을 만든다.

### 사용 도구

Claude Code (Opus 5), GSAP 3, Chrome MCP

### 대표 프롬프트

```text
로딩화면이랑 메인화면 gsap로 애니메이션 만들어주고 (게임처럼)
눌렀을때 페이드아웃될때 검은색화면 바뀌는것도 넣어주고

메인화면 남는 여백 없게 가능해? 어떤 뷰에서든

로딩화면 프로그레스바 없애주고, 장식 도는 애니메이션 없애고,
배경은 흰색 LOADING은 검은색. 대신 배경에 글리치 효과 조금씩 줘.

글리치 효과는 가로 선보다는 gsap 효과를 이용해서 조금씩 번개같은 느낌으로 세로 픽셀로.
```

### AI 제안 요약

연출을 요소별 CSS 애니메이션으로 흩뿌리지 않고 GSAP 타임라인 하나로 묶었다.
화면 전환은 `ScreenFade` 한 컴포넌트로 통일해, 검게 덮인 시점에 다음 화면으로 넘긴다.
여백 문제는 배경만 16:9 무대 밖으로 빼서 `cover`로 덮어 해결했다.

### 최종 반영

- `LoadingScreen.tsx`, `ScreenFade.tsx`, `titleAssets.ts` 신규
- `TitleScreen.tsx` 등장 타임라인, `HUDOverlay` 로딩·전환 상태 관리
- `ornament.png` 상하 반전 저장, `theme.z`에 `loading`·`transition` 추가

### 사람의 수정 및 판단

- 장식의 상하 반전을 CSS `transform`으로 두면 GSAP이 같은 속성을 덮어써 충돌한다.
  파일 자체를 뒤집는 쪽이 코드도 짧고 충돌도 없어 그렇게 했다.
- 첫 구현은 로딩 페이드아웃이 **끝난 뒤** 시작 화면을 붙여서, 걷히는 동안 화면이 탁해졌다.
  `onReveal`을 추가해 걷히기 시작할 때 붙이도록 고쳤다.
- 여백 제거를 화면 전체 `cover`로 하면 타이틀이 잘릴 수 있어, 배경만 `cover`하고
  타이틀은 16:9 무대에 남겼다. 구도가 Figma와 약간 달라지는 것은 감수했다.
- 검증 중 자동화 브라우저의 탭이 백그라운드로 내려가 `requestAnimationFrame`이 늦춰졌고,
  연출이 멈춘 것처럼 보였다. 코드 결함으로 오인하지 않도록 DOM 상태를 직접 읽어 확인했다.
- 로딩 화면은 Figma 시안이 없어 임시안이다. 임의 확정하지 않고 OQ-027로 등록했다.

### 관련 파일

`src/components/ui/LoadingScreen.tsx`, `src/components/ui/ScreenFade.tsx`,
`src/components/ui/TitleScreen.tsx`, `src/components/ui/titleAssets.ts`,
`src/components/HUDOverlay.tsx`, `src/styles/theme.ts`, `public/assets/title/ornament.png`

## AI-006 — 시작 화면 메뉴·설정·배경음악·커스텀 커서

### 목적

시작 화면을 "아무 키" 방식에서 메뉴 방식으로 바꾸고, 배경음악과 설정, 커스텀 커서를 붙인다.

### 사용 도구

Claude Code (Opus 5), GSAP 3, Chrome MCP

### 대표 프롬프트

```text
배경음악 넣을거야. 로딩 화면 들어가면 나오게. 백그라운드 뮤직으로 넣어줘 메인에만.

"아무키나 누르세요" 보다는 처음부터 / 이어하기 / 설정 이렇게 하는게 좋을거같고
font는 pretendard, weight는 light, color = white.
뒷 배경은 사각형인데 투명도 좀 낮추고 그라데이션으로 왼쪽 끝 오른쪽 끝에는
투명도 더 낮추고 가운데에만 진한색. 설정창은 간단하게 소리설정정도로만.
첫 방문일 경우 소리 안나오니까 팝업 지금 톤 맞춰서 하나 띄우자.

마우스 포인터도 바꾸자. mobicom에 잘 만들어놨으니 가져와서 색만 빨간색으로.
시작하기 버튼 파란색 line 지워. 톤 안맞잖아.
```

### AI 제안 요약

자동 재생 차단은 우회할 수 없으므로 첫 방문 안내 팝업을 소리 진입 게이트로 삼았다.
커서는 mobicom의 `CursorFollower`를 가져오되 `@gsap/react`가 이 프로젝트에 없어
`useLayoutEffect`로 바꾸고 색만 교체했다.

### 최종 반영

- `TitleBgm.tsx`, `SettingsPanel.tsx`, `FirstVisitPrompt.tsx`, `CursorFollower.tsx` 신규
- `TitleScreen`의 안내 문구를 메뉴 3개로 교체, `HUDOverlay`가 볼륨·첫 방문 상태 관리

### 사람의 수정 및 판단

- "이어하기"는 저장 기능이 없다. 세이브·로드는 CLAUDE.md 규칙 3의 승인 필요 항목이라
  임의로 구현하지 않고 비활성 표시만 하고 OQ-028로 등록했다.
- 파란 포커스 링을 완전히 지우면 키보드 사용자가 위치를 잃는다.
  지우는 대신 색만 붉은 톤으로 바꿔 요구와 접근성을 함께 만족시켰다.
- 첫 구현에서 안내 팝업 뒤로 로딩 화면이 비쳐 지저분했다. 안내가 떠 있는 동안
  로딩을 렌더하지 않도록 고쳐 순서를 안내 → 로딩 → 시작 화면으로 고정했다.
