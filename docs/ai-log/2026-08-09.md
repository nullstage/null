## AI-018 — OQ-031 수정: 방 1 무전투 텔레메트리가 방 3 분석을 희석하던 문제

### 목적

병합 과정에서 발견하고 OQ-031로만 등록해 뒀던 문제(방 1처럼 전투가 없던 방의 빈
텔레메트리가 `previousTelemetry`로 그대로 넘어가 다음 방 65/35 가중 분석을 희석함)를
실제로 고치기 위해서다.

### 사용 도구

Claude Code (Sonnet 5)

### 대표 프롬프트

```text
머지하고 발견한 문제도 수정하자 성향 판정 희석되는거
```

### AI 제안 요약

- `RunState.completeRoom()`이 방을 클리어할 때마다 무조건 `currentTelemetry`를
  `previousTelemetry`로 넘기던 것을, 그 방에 실제 신호(적중 또는 대시 1회 이상)가
  있었을 때만 넘기고 없으면 `null`로 두도록 수정.
- 구현 중 재검토하며, 이 희석이 근거리/원거리 "비율" 판정에는 수학적으로 영향이
  없고(분자·분모가 같은 배율로 줄어드는 구조라 비율 불변) 대시 횟수 절대값 기준인
  MOBILE 판정에만 실제로 영향을 준다는 점을 발견 — 처음에 문서에 적었던 "판정이
  전반적으로 약해진다"는 설명을 정정했다.

### 최종 반영

- `src/game/systems/RunState.ts`의 `completeRoom()`에 `previousHadSignal` 판정 추가.
- `window.runState` 개발용 훅으로 실제 전투 없이 방 클리어를 직접 재현해 검증:
  수정 전에는 방 2 클리어 후 `previousTelemetry`가 방 1의 빈 텔레메트리였고, 수정
  후에는 `null`(=방 2가 100% 가중치)임을 확인. 방 2→방 3처럼 둘 다 실신호가 있는
  정상 케이스는 그대로 65/35가 유지되는 회귀 없음도 함께 확인.
- `npm run typecheck`, `npm run lint`, `npm run build` 모두 통과.
- OQ-031을 RESOLVED로, `docs/WorkLog.md`에 검증 근거를 포함한 수정 기록을 추가.

### 사람의 수정 및 판단

- "판정이 희석된다"는 최초 가설을 구현 중 수학적으로 재검증해 스스로 정정했다 —
  실제로 영향받는 것은 MOBILE 대시 판정뿐이라는 점을 과장 없이 문서에 반영.
- 검증 스크립트(`verify-dilution-fix.mjs`)는 확인 후 삭제해 저장소에 남기지 않았다.

### 관련 파일

## AI-019 — 화염·맹독 속성탄 킬 시 크래시 버그 분석·수정

### 목적

수 없었다.

### 사용 도구

### 대표 프롬프트

```text

적이 좀 커지면서 크래시났어 근데 맹독탄을 추가한 직후였어
```

### AI 제안 요약

- 스택만으로 위치를 못 좁혀 사용자에게 재현 상황을 되물었고, 답변("적이 커지는"
  히트펀치 연출·맹독탄 직후·다음 발 시도 시점)을 근거로 지연 데미지 틱(`delayedCall`)

  적을 죽이면 `BaseEnemy.defeat()`가 콜백 도중 `sprite`를 null로 만든다는 것을 소스
  추적으로 확인. 같은 구조가 `BossScene.ts`에도 그대로 복제돼 있어 총 4곳을 특정했다.

### 최종 반영

- 4곳 모두 `takeDamage()` 호출 전에 `sprite.x`/`sprite.y`를 미리 캡처하도록 순서 변경.
- `npm run typecheck`, `npm run lint` 통과 확인.

## AI-020 — 방 1 서사 종료 직후 키맵 모달 추가 (P-038, DEC-020)

### 목적

사용자가 "스토리 이후에 조작키 안내 모달을 띄우자"고 요청한 것을 구현하기 위해서다.

### 사용 도구

Claude Code (Sonnet 5)

### 대표 프롬프트

```text
브랜치 새로 파서 처음에 스토리 이후에 튜토리얼 모달창? 같은거 띄우려고 해
키매핑 어떤 키에 어떤 기능이 들어가있는지 보여주는 그런거
```

### AI 제안 요약

- 구현 전에 `DialogueBox.tsx` 주석을 읽고, "서사에는 키 이름을 넣지 않는다·키 안내는
  설정 화면이 맡는다"는 기존 결정과 이번 요청이 정면으로 충돌함을 먼저 짚었다. OQ-026도
  그 지점에서 계속 `OPEN`이었다.
- 어느 쪽이 맞는지 임의로 정하지 않고 두 가지를 사용자에게 물었다: (1) 대화는 그대로 두고
  뒤에 별도 모달을 잇는가, 대화 자체를 키 안내형으로 바꾸는가, (2) 매번 보여줄지 최초
  1회만 보여줄지 — `DialogueBox`가 "재방문 시 건너뛰기" 로직에서 씬 자기 일시정지와
  경합해 영원히 멈추던 과거 버그를 참고 정보로 함께 제시했다.
- 사용자가 "대화 후 별도 모달·최초 1회"를 선택한 뒤에야 구현: `KeyMapModal.tsx` 신설,
  `HUDOverlay`에서 `DialogueBox.onDone` → (최초면) `KeyMapModal` → `game:resume` 순서로
