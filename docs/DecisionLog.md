## DEC-001 — 프로젝트 핵심 경험

- 날짜: 2026-08-06
- 상태: ACCEPTED

### 결정

게임의 핵심은 플레이어 전투 분석, 다음 방 카운터 구성, 플레이 스타일 전환을 통한 역기만, 보스 패턴 변화로 고정한다.

### 이유

4일 안에 구현 가능한 범위에서 Counter Director가 단순 난이도 조절이 아니라 플레이어와 수 싸움을 벌이는 시스템임을 명확히 보여주기 위해서다.

### 영향

- 방 3은 분석 결과에 따라 적 구성이 달라져야 한다.
- 보스는 성향별 패턴 가중치를 사용해야 한다.
- 분석 결과와 예측 실패가 UI에 보여야 한다.

- 날짜: 2026-08-06
- 상태: ACCEPTED

- 실시간 LLM 호출: 네트워크 실패와 응답 지연 때문에 제외

## DEC-005 — 기술 스택과 배포 형태

- 날짜: 2026-08-06
- 상태: ACCEPTED
- 관련 질문: OQ-001, OQ-002

### 결정

다음 스택으로 확정한다.

```text
Next.js (App Router) — 셸과 UI 레이어
Phaser 3 — 게임 런타임
GSAP — UI 연출
Emotion — UI 스타일
TypeScript — 전 영역
```

배포는 Next.js 정적 내보내기(`output: "export"`)로 생성한 정적 파일을 GitHub Pages에 올린다.
저장소는 `nullstage/null`을 사용하고 `basePath`는 `/null`로 설정한다.

### 이유

- 팀원이 사용할 스택이 Phaser·Next.js·GSAP·Emotion으로 정해져 있다.
- 정적 내보내기를 쓰면 서버 없이 GitHub Pages에 그대로 올릴 수 있어 DEC-002와 충돌하지 않는다.
- Phaser 메이저 버전은 3으로 고정한다. `MVP_PLAN.md`와 `CLAUDE.md`가 Phaser 3을 전제로 작성되어 있고, 팀원이 참고할 전투·보스 구현 패턴 자료도 3 기준이 압도적으로 많다.

### 대안

- Vite + Phaser 단독: 더 가볍지만 팀원 스택과 어긋나고 Emotion·GSAP UI 레이어를 살리기 어렵다.
- Next.js 서버 렌더링 사용: GitHub Pages가 정적 호스팅이라 불가능하다.
- Phaser 4: 최신이지만 자료가 적고 MVP_PLAN 전제와 어긋난다. 필요하면 별도 결정으로 올린다.

### 영향

- Phaser는 `window`에 의존하므로 정적 프리렌더 중 실행되면 안 된다. 캔버스 컴포넌트는 `ssr: false` 동적 임포트로만 마운트한다.
- 정적 경로 문제 때문에 에셋 경로는 `basePath`를 반영해야 한다.
- `MVP_PLAN.md` §11 파일 구조를 Next.js 구조에 맞게 갱신한다.

## DEC-006 — UI를 React DOM 오버레이로 분리

- 날짜: 2026-08-06
- 상태: ACCEPTED
- 관련 질문: OQ-001

### 결정

분석 팝업, 강화 선택, 결과 리포트, 디버그 패널은 Phaser 내부가 아니라 캔버스 위에 얹는 React 컴포넌트로 구현한다.
Phaser와 React는 단일 이벤트 버스로만 통신하고 서로의 객체를 직접 참조하지 않는다.

```text
Phaser  --emit-->  EventBus  --subscribe-->  React UI
React   --emit-->  EventBus  --subscribe-->  Phaser
```

### 이유

- Emotion과 GSAP을 스택에 넣은 목적이 UI 스타일과 연출이므로 UI가 DOM에 있어야 의미가 있다.
- 팀원은 Phaser 씬과 전투에 집중하고, 시스템 담당은 React UI에 집중할 수 있어 파일 충돌이 줄어든다.
- 텍스트 레이아웃, 반응형, 접근성 처리가 Phaser Text보다 쉽다.

### 대안

- Phaser 내부 UI: MVP_PLAN 원안이지만 Emotion·GSAP이 사실상 사용되지 않는다.
- 혼합: 전투 HUD만 Phaser 내부. 유효한 절충안이라 전투 HUD는 이후 필요 시 Phaser로 옮길 수 있다.

### 영향

- `MVP_PLAN.md` §11의 `src/game/ui/*.ts`는 `src/components/ui/*.tsx`로 대체된다.
- 게임 로직은 React 상태에 의존하지 않아야 한다. UI가 없어도 런은 성립해야 한다.

## DEC-007 — 작업 책임 분리

- 날짜: 2026-08-06
- 상태: ACCEPTED

### 결정

| 영역 | 담당 | 범위 |
|---|---|---|
| 전투 | 팀원 | 플레이어 조작·공격·피격, 적 3종 동작, 보스 상태와 패턴 실행, 타격 피드백 |
| 시스템 | 본인 | 게임 상태, 텔레메트리, Director 정책, 강화, React UI, 이벤트 버스, 배포 |

현재 단계에서는 시스템 영역만 동작하도록 구현하고, 전투 영역은 타입과 호출 시점이 확정된 빈 스텁으로 남긴다.

### 이유

전투 감각은 직접 만드는 사람이 잡아야 하고, 미리 구현해두면 팀원이 버리는 코드가 된다.
반대로 계약과 호출 시점이 없으면 나중에 통합할 때 서로의 파일을 고쳐야 한다.

### 영향

- 스텁 파일에는 구현 대신 `// 팀원 담당` 주석과 시그니처만 둔다.
- 텔레메트리 기록 호출 지점은 시스템 담당이 미리 심어두고, 팀원은 그 자리를 지운다.
- 공통 타입(`src/game/types/game.ts`)은 시스템 담당이 관리하며 임의로 변경하지 않는다.
