- 파일을 열거나 사소한 문구를 바꾼 사실까지 모두 기록하지 않는다.

  - 원인: 안내와 로딩을 동시에 렌더했다. 안내의 반투명 배경 너머로 흰 로딩과 글리치가 보였다.
  - 수정: 안내가 떠 있는 동안에는 로딩을 렌더하지 않는다. 순서를 안내 → 로딩 → 시작 화면으로 고정했다.

- **`localStorage` 값을 초기 상태로 읽으면 하이드레이션이 어긋난다.**
  - 원인: 정적 프리렌더에는 `window`가 없다. (DEC-005)
  - 수정: 마운트 뒤 `useEffect`에서 한 번 읽는다. `react-hooks/set-state-in-effect`는 이 지점만 예외 처리했다.

#### 검증

- `npm run typecheck` / `npm run lint` / `npm run build` 통과
- 브라우저 직접 확인
  - 첫 방문 안내 → 버튼 클릭 → 로딩 → 시작 화면 메뉴 등장
  - 메뉴 선택 강조(붉은 그라데이션), 이어하기 비활성 표시, 설정 패널 열림·볼륨 45 표시
  - 커스텀 커서가 버튼 위에서 확대되고, 포커스 링이 붉은색으로 표시됨
  - 콘솔 오류 0

- 배경음악은 실제 청취 확인이 필요하다. 자동화로는 소리를 검증할 수 없다.

### 18:10 — 조작키 변경 기능

- 디버그 키(F1·F2)는 변경 대상에서 제외했다. 브라우저 단축키와 겹치기 쉽다.

- `KEY_BINDINGS`를 새 객체로 갈아끼우지 않고 내용만 바꾼다.
  이미 import한 쪽이 옛 참조를 들고 있으면 변경이 반영되지 않는다.

- `npm run typecheck` / `npm run lint` / `npm run build` 통과
- 브라우저 직접 확인
  - 점프 `SPACE` → `Z` 변경, `localStorage`에 `{"JUMP":"Z"}` 저장
  - 공격에 `Z` 지정 시 점프가 `J`를 받아가는 스왑 동작 확인 (`{"JUMP":"J","ATTACK":"Z"}`)

  - 콘솔 오류 0

### 플레이어 스프라이트 적용과 대시 연출

- 상태: DONE (실플레이 일부 확인)
- 관련 계획: P-020
- 관련 결정: DEC-011
- 관련 질문: OQ-024

#### 작업

- `sprite-gen` + Codex로 base 도트 한 장에서 4상태 아틀라스를 뽑아 붙였다.
  288x192, 48x48 셀, idle 4 / run 6 / attack 6 / jump 4.
- `BootScene`이 시트를 로드하고 애니메이션을 부팅 때 한 번만 등록한다.
- 대시 잔상을 붉은 실루엣 + 가산 블렌드로 바꾸고, 진행 반대로 밀리며 늘어나게 했다.
- 공중 대시가 포물선을 그린다. 지상 대시는 회피기라 직선을 유지한다.

#### 오류 및 원인

- **sprite-gen의 codex provider가 항상 실패한다.**
  세션 jsonl의 `image_generation_call` status가 `generating`으로 남아 파서가 포기하는데,
  이미지는 `image_generation_end`에 base64로 멀쩡히 들어 있다. 추출 헬퍼로 우회했다.
- **공중 대시가 일자로 보였다.** 중력 비율만 올려서는 부족했다.
  대시가 150ms라 그 사이 낙차가 5px 남짓이다. 시작에 상승 속도를 실어 띄운 뒤
  떨어지게 해야 호로 읽힌다.
- **관성을 넣자 잔상이 중간에 끊겼다.** 잔상을 `isDashing` 동안만 남기고 있었다.
  이동 속도보다 빠른 동안에는 대시가 끝나도 잔상을 잇는다.
- **공중에서 방향키를 누르면 대시가 끊겼다.** 관성 구간에서 수평 속도를
  이동 속도로 즉시 덮어쓰고 있었다. 같은 방향이고 관성이 더 빠르면 덮어쓰지 않는다.
  반대로 꺾을 때는 그대로 받는다. 공중 제어권까지 뺏으면 답답하다.
- **대시 후반에만 잔상이 뭉쳤다.** 감속 구간에서는 이동 거리가 좁아 잔상이 겹치는데
  가산 블렌드라 밝기가 쌓인다. 알파를 수평 속도에 비례시켜 해결했다.

#### 남은 문제

- **상태별 캐릭터 크기 편차.** 발 위치는 정렬됐으나 키가 다르다.
  idle/jump는 40으로 일정, run 33~40, attack 24~40. 원인은 추출이 아니라 생성이다.
  `--style`에 스케일 잠금을 넣고 재생성했지만 측정값이 그대로였다.
  `prepare --force`가 `frames/`를 남겨 extract가 옛 프레임을 재사용한 것으로 보인다.
  다음에는 `frames/`를 지우고 extract부터 다시 해야 한다.
- 실플레이 검증은 사람이 해야 한다. 자동화 탭이 백그라운드로 내려가면
  `requestAnimationFrame`이 멈춰 전투 화면 진입 자체가 불가능하다.
