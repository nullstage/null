# AI 사용 기록 — 2026-08-09

## AI-017 — 팀원 브랜치 병합: 설계 충돌 조정, 보스 SLAM 낙사 버그 재수정

### 목적

`feat/director-policy-tuning` PR을 main에 병합하기 전, 팀원의 대규모 병합(패링·
아티팩트·상점·NPC·보스 전면 개편·방 1 튜토리얼 개편 등)과 실제로 겹치는지 확인하고
안전하게 합치기 위해서다.

### 사용 도구

Claude Code (Sonnet 5)

### 대표 프롬프트

```text
지금 팀원 브랜치가 메인에 머지 됐거든? 한번 내꺼 머지 되나 봐봐
```
(확인 후 충돌 상세 보고 → 사용자가 "응 그렇게 진행해줘"로 병합 진행 승인)

### AI 제안 요약

- `gh pr view`와 `git merge-tree`(비파괴)로 먼저 충돌 범위를 파악할 것을 제안 —
  실제로 머지하기 전에 무엇이 부딪히는지 알아야 안전하다고 판단.
- 텍스트 충돌 6개(Plan.md·WorkLog.md·ai-log·rooms.ts·Boss.ts·CombatScene.ts) 중
  코드 충돌 3개는 기계적으로 풀 수 있었지만, `rooms.ts`/`CombatScene.ts` diff를 먼저
  정독한 결과 팀원의 "방 1 무전투화"가 내 DEC-014(당시 번호, 현 DEC-016)의 설계
  전제(방 1 분석 → 방 2 반영) 자체를 무너뜨렸음을 발견해 사용자에게 먼저 보고.
  단순 충돌 해결로 넘어가지 않고 대안(방 2 1웨이브 텔레메트리로 대체 등 3가지)을
  제시해 사용자가 고르게 했다.
- 팀원의 "부활 루프"(사망해도 런 유지, 마을로 복귀)가 MVP_PLAN이 전제하던 permadeath
  로그라이크 구조 자체를 바꾼 것도 함께 보고 — 이미 사용자가 팀원과 확정한 변경(코드
  주석에 "사용자 확정"으로 명시)이라 되돌리자고 제안하지 않고 사실만 전달.

### 최종 반영

- 사용자가 "방 2 1웨이브 텔레메트리로 대체"를 선택. `RoomController.resolveWaveOverride`
  훅을 신설하고 `CombatScene`이 방 2 1웨이브 클리어 시점에 스타일을 분류해 2·3웨이브
  프리셋(`room_2_soft_*`)을 고르도록 구현. 기존 `resolveRoomId`는 제거.
- 병합된 main의 보스(팀원이 전면 개편한 버전)에도 어제와 같은 SLAM 낙사 버그가
  그대로 있음을 먼저 재현한 뒤, 같은 원인(`setAllowGravity(false)`가 `enemyBodies.add()`
  보다 먼저 호출됨)을 팀원의 새 스폰 코드(스프라이트 스케일·프레임 시스템 추가) 위에
  다시 적용했다. `git merge`가 이 3줄짜리 순서만 정확히 분리해 충돌 없이 병합해 줬다.
- DEC-013·DEC-014 번호가 main과 겹친 것을 발견해 내 결정만 DEC-015·DEC-016으로
  재번호(코드 주석·문서 전체, 팀원 것은 그대로 둠).
- 어제 만든 AnalysisPanel의 "방2/방3 예고 강약 차등화"가 방 1 무전투화로 분석
  시점이 하나로 줄면서 죽은 분기가 된 것을 확인하고 되돌렸다.

### 사람의 수정 및 판단

- 설계 충돌(게임 루프 변경급)을 발견했을 때 곧바로 고치지 않고 사용자에게 보고 후
  대안을 제시해 결정을 받았다 — CLAUDE.md의 "게임 루프 변경은 질문한다" 원칙.
- 완료 보고 전 실제 브라우저 검증 규칙에 따라, 헤드리스 자동화로 방 2 실전투(1웨이브
  → 2웨이브 전환)를 반복 시도했으나 팀원의 새 전투 난이도(웨이브당 4기, 부활 루프)에서
  자동화가 계속 사망해 완주하지 못했다. 이걸 감추지 않고, 대신 팀원이 dev용으로 이미
  노출해 둔 `window.phaserGame`/`window.runState` 훅으로 보스 씬에 직접 진입해
  `setBossWeights`로 SLAM을 100% 강제한 뒤 45초간 낙사 여부를 결정적으로 검증하는
  대체 경로를 스스로 찾아 실행했다. 못 한 것과 확인한 것을 구분해서 보고했다.
- 병합 과정에서 새로 발견한 문제(방 1의 빈 텔레메트리가 방 3 분석을 35%만큼 희석)를
  범위 밖이라 임의로 고치지 않고 OQ-031로 등록만 했다.
